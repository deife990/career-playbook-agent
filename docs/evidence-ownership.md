# 본인 기여와 팀 결과 구분

| 분류 | 자료가 보여주는 내용 | 활용 범위 |
|---|---|---|
| A | 본인이 직접 수행한 행동 | 정확한 행동 확인 후 경력 근거 |
| B | 본인에게 할당된 일과 그 이후 실제 실행 | 할당만으로는 부족; 실행까지 확인 |
| C | 다른 사람이 구체적인 본인 기여를 확인 | 보강 근거; 정확한 사용자 확인 필요 |
| D | CC, 수신, 회의 초대·참석, 채널 참여만 | 참여 맥락; 개인 업무 수행 주장 불가 |
| E | 사건이나 팀 결과만 | 상황 맥락; 개인 행동 주장 불가 |

“I coordinated …”라는 기록, 업무 요청과 완료 기록, 다른 사람의 감사 기록은 서로 다른
근거입니다. 다른 사람이 고맙다고 했다는 이유로 프로젝트를 주도했다고 쓰지 않습니다.
A/B여도 관리자·리더였다는 뜻은 아닙니다. “팀이 12개 현장을 이전했다”는 자료에서 본인이
직접 한 일을 알 수 없다면 “내가 12개 현장 이전을 주도했다”로 바꾸지 않습니다.

확인할 때는 “이 요약은 맞나요?”만 묻기보다 직접 한 행동, 범위, 개인 결과와 팀 결과를
구분해 보여줍니다. 확인한 뒤 문구가 달라지거나 충돌이 생기면 다시 확인합니다. 사용자에게
JSON이나 해시 입력을 요구하지 않습니다. Copilot 요약과 자기 확인은 외부 검증이 아닙니다.

같은 사건의 자료는 하나의 경험으로 묶고 출처만 보강합니다. 서로 다른 장애나 기간을
키워드만 보고 합치지 않습니다. 숫자를 더하거나 가장 큰 결과를 선택하지 않습니다.
기존 확인된 내용과 충돌하면 덮어쓰기 대신 확인과 별도 수정 이력을 남깁니다.
