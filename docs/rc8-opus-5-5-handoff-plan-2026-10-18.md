## 2. 현재 최종 평가의 식별값 오류 1건을 처리한다

대상은 **Claude `context-model-roundtrip` 1회차**다. 원본 보고의 status는 PASS지만 감사상 ERROR이며, `modelUsage={}`, 토큰 관측값 모두 0, stderr에는 모델 정보가 없다. 이는 실제 토큰 사용량 0·과금 0·특정 모델 사용을 증명하지 않는다.

먼저 해당 실행에 직접 연결된 기존 로그에 독립적인 실제 모델 식별값이 있는지 확인한다. 주변 응답·기본 설정·현재 모델 이름을 대신 채우지 않는다. 현재 보존 자료에서는 식별값을 찾지 못한 상태다. 심판만 다시 호출해도 subject 식별값은 복구되지 않는다.

**추가 증거가 없다면 다음 선택은 사용자 승인 사항이다.** 기존 지시는 “해결할 수 없는 오류이면 중단”이고, 하네스 수정은 지문·진행분 영향을 먼저 설명하고 승인받도록 했다. 이 계획 작성 요청이 해당 지시를 해제하지 않는다.

권장 승인안은 현재 **최종 평가 오류 한 건에 한해** 새 subject 1회와 기존 설정의 judge 1회를 허용하는 것이다. 이전 개발 `evd-07-privacy` ERROR의 재생성은 계속 제외한다.

승인 후의 복구 방식:

1. 원래 stdout/stderr, transcript, checkpoint, 관측 PASS, 감사 ERROR를 모두 그대로 보존한다.
2. 별도 새 attempt 폴더에서 동결 `run_case`를 이용해 대상 슬롯만 실행한다. 미확인 모델이 든 기존 subject checkpoint를 재사용하지 않는다.
3. 패키지·입력·프롬프트·교차 심판·전체 3회 프로토콜은 유지한다. 대상 1회차의 오류 복구가 나머지 2·3회차 재실행이나 `--runs 1` 진단 전환을 뜻하지 않는다.
4. 유효 완료 보고는 원본과 별도로 만들고, 원본 감사 ERROR → 승인된 새 attempt → 최종 슬롯 판정의 연결을 기록한다. 원래 보고서의 PASS를 덮어쓰거나 원본 오류를 삭제하지 않는다.
5. 실제 subject/judge 모델 식별값을 검증한다. 새 결과가 FAIL이면 그대로 보존하고 출시 실패 수에 포함한다. 다시 돌려 지우지 않는다.
6. 복구 실행기의 변경이 필요하면 먼저 변경 범위와 실행 지문 영향을 설명한다. 패키지·스위트·평가 프롬프트/모델 의미 변경이 필요한 경우 기존 진행분을 그대로 유효하다고 선언하지 않는다.

`/private/tmp/careerpilot-rc8-release-batch.py`는 참고용 기존 도구다. 전체 이전 행의 모델 정보를 검사하지 않고 raw PASS를 건너뛰며, 현재 시나리오가 끝난 뒤에만 모델 정보를 확인한다. **그대로 실행하면 이번 오류를 해결하지 못한 채 뒤의 실행만 진행할 수 있다.** 재개 전에 별도 감사와 격리 처리를 완료한다. 임시 도구는 보존 tar의 `execution-tools/`에도 있다.

**이 단계 완료:** 승인 범위 안에서 provenance가 확인된 유효 판정 1건을 얻거나, 해결 불가 상태와 필요한 결정을 보고하고 중단한다. 승인 없이 재생성·검사 완화·자동 PASS 승격을 하지 않는다.

현재 후보에서 확인된 Claude `concise-second-opportunity` 2회차 FAIL은 미확인 질·방법 수식어를 사실 포지셔닝에 붙인 기존 범위 부풀리기다. 해결됐다고 표시하지 않는다.

실패 0건은 해당 결함을 “해결됨”으로 표시하는 조건이며 이번 전체 출시 조건은 아니다. 남은 자동 FAIL과 자동 PASS에서 별도로 발견한 실제 문제를 README의 알려진 문제에 공개한다. 플랫폼 간 성능 순위 비교를 하지 않는다.

**미달이면 중단:** 추가 후보 수정·튜닝·같은 설정 재실행으로 실패를 지우지 않는다. rc.7 표기를 유지하고 결과와 남은 문제를 기록한다.

**이 단계 완료:** 날짜와 근거 보고서가 연결된 rc.8 상대 기준 판정 JSON/문서. 전체 안전성 보장이나 브라우저 인증으로 표현하지 않는다.

## 5. 동결 홀드아웃 v1을 후보에만 1회 실행한다

최종 C 기준을 만족한 뒤 실행한다.

- `evals/variants/e-stage/holdout-manifest-v1.json`의 시나리오 9개를 양쪽에서 각 1회, 총 18판정.
- 입력·manifest를 수정하지 않고 실제 실행 override만 n=1로 명시한다.
- tier별 기존 심판 경로와 preloaded 맥락을 유지한다.
- 기존 `run_variant_evals --mode final`은 critical 3회가 기본이므로 그대로 실행하면 이번 승인량을 넘는다. 동결 manifest와 엔진을 보존하는 별도 실행 계층의 n=1 설정을 사용한다. 구현 변경이 필요하면 지문·승인 경계를 먼저 확인한다.
- 결과는 C 및 개발 진단과 분리해 공개한다. 홀드아웃 행동 FAIL은 출시 조건으로 쓰지 않지만 숨기지 않는다. 기술적 오류·할당량 소진은 승인된 중단 조건에 따라 처리한다.
- speaker 단언의 의도 추론 금지와 W08 계약의 불확실한 복수 가설 허용 불일치를 알려진 평가 이슈로 한 줄 기록한다.
- holdout v2 재설계, 입력 수정, 추가 반복·수정 회차를 하지 않는다.

**이 단계 완료:** 18건의 판정·원문·모델 식별값·설정·지문이 별도 보고서와 보존본에 존재.

## 6. rc.8 문서와 설치 패키지를 준비한다

C 출시 기준 충족 및 승인된 평가 완료 후 수행한다.

1. `VERSION`을 `1.2.0-rc.8`로 변경한다.
2. `CHANGELOG.md`에 실제 개선 내용·검증 범위·잔여 실패를 적는다.
3. `README.md`에 버전, 설치 파일, 플랫폼별 C 결과, 반복·심판·컨텍스트, 알려진 문제를 갱신한다. public upload 전의 다운로드 링크는 게시 예정임을 명시하고 로컬 파일도 안내한다.
4. `docs/GATES.md`, `docs/review-improvement-progress.md`, `docs/rc8-release-progress-2026-10-17.md`와 현재 배포 안내를 일관되게 갱신한다. 과거 증거는 삭제하거나 새 기준으로 소급 수정하지 않는다.
5. 원본에서 어댑터를 재생성한다. `adapters/`는 직접 편집하지 않는다.
6. 평가된 동결 패키지와 버전 변경 후 패키지의 파일별 차이를 확인한다. 승인된 버전 메타데이터만 바뀌었는지 기록한다. 런타임 규칙이 달라지면 이전 평가가 새 패키지를 인증한다고 주장하지 않는다.
7. 버전 변경 후 pytest·정적 검사·예산/참조/패키지 검사를 실행한다.
8. 아래 설치 ZIP 두 개와 체크섬을 생성한다. 재빌드의 바이트 동일성, 압축 내부 경로·참조·파일 목록, 개발 도구/로그 미포함, 최종 SHA-256을 확인한다.

예상 산출물:

- `dist/releases/careerpilot-chatgpt-v1.2.0-rc.8.zip`
- `dist/releases/careerpilot-claude-v1.2.0-rc.8.zip`
- `dist/releases/checksums-v1.2.0-rc.8.sha256`
- `evals/reports/`의 최종 C·홀드아웃·판정·패키지 동일성·증거 보존 기록

주의: 기존 `scripts.release_readiness.py`와 `package_release --require-ready`는 전부 PASS인 기존 조건을 요구해 새 상대 기준과 다르다. **이 검사를 실행해 실패했다고 출시 기준을 임의로 바꾸거나, FAIL을 PASS로 고쳐 통과시키지 않는다.** 최신 승인 정책의 별도 무호출 감사를 통과한 근거를 남긴 뒤 일반 패키징 기능을 사용한다. 이를 기존 strict readiness PASS라고 표기하지 않는다. 동결 엔진/검증기를 임의로 완화하지 않는다.

버전과 패키지가 달라지므로 rc.7의 브라우저 제외 지문 기록을 rc.8 인증으로 재사용하지 않는다. 기존 사용자 지시의 브라우저 제외 범위를 rc.8의 실제 지문과 연결해 기록하되 브라우저를 실행하지 않는다.

**이 단계 완료:** 최종 패키지 내용이 평가한 런타임과 동등하고 설치 ZIP·체크섬·문서가 일치한다. 실제 배포/설치 성공을 주장하지 않는다.

## 7. 커밋과 최종 보고

기능 브랜치에만 결과·문서·필요한 승인된 실행 도구 변경을 의미 있는 단위로 커밋하고 각 단위 종료 때 3–5줄로 보고한다. 기존 추적 규칙대로 `dist/` 설치 파일을 전달하며, Git에 강제 추가할지 임의로 바꾸지 않는다.

최종 보고는 다음만 짧게 제시한다.

- 출시 조건 충족 여부 및 검증 한계.
- 플랫폼별 실패 수와 각자의 rc.7 기준.
- 남은 알려진 문제.
- 만든 파일의 절대 경로/체크섬과 로컬 커밋.
- 사용자 직접 실행할 태그·푸시·업로드가 남아 있다는 점.

## 하지 않을 작업과 중단 조건

제외: D 별칭·중복 경로 제거, F 상황별 로딩, holdout v2, 이전 개발 evd-07 ERROR 재생성, 추가 개발 진단, 전체 스타일 정리, 과거 리포트 이동, 브라우저 검증, main 병합, 푸시, 태그, 릴리스 업로드, 추가 결제·리셋 크레딧, cron/heartbeat.

중단: 할당량 소진, 해결할 수 없는 오류, 최종 출시 기준 미달. 기존 출시 정책의 빠른 확인 단계는 완료됐으므로 다시 실행하지 않는다. 오류를 행동 FAIL로 바꾸거나 관측 PASS를 유효 PASS로 승격해 완료를 만들지 않는다.

최초 착수는 **무호출 재개 감사와 현재 오류 1건의 처리 결정**이다. 이 문서만 전달받고 곧바로 236건을 실행하거나 패키지를 수정하지 않는다.
