# 업무기록에서 경력 근거 찾기

“이 공고에 쓸 경험을 더 찾아보자”라고 말하세요. CareerPilot은 공고의 요구사항을 먼저
정리하고, 이미 제공한 경력·이력서·스토리·지원 기록·실제 면접 답변부터 확인합니다.
이미 확인한 일을 반복해서 묻지 않고, 부족한 근거만 선택해 찾습니다.

| 상태 | 뜻 | 다음 행동 |
|---|---|---|
| Strong | 해당 요구사항을 충분히 뒷받침하는 직접 근거 | 추가 검색 생략 |
| Usable | 지원에 사용할 수 있는 확인된 근거 | 보통 재사용, 필요할 때만 보강 |
| Thin | 관련 힌트는 있지만 직접 한 일·범위·결과가 부족 | 중요한 항목부터 탐색 |
| Unknown | 경험의 존재 여부가 미확인 | 업무기록이나 구체적 질문으로 확인 |
| Confirmed Gap | 확인된 요구사항과 확인된 부재·불일치 | 해당 항목의 탐색 중단 |

이 표는 v1.1의 JD 매칭 표나 채용담당자 검토 등급과 별개입니다. 이력서에 없는 내용이나
검색에서 나오지 않은 내용을 “경험 없음”으로 바꾸지 않습니다. 공고가 없다면 임시 목표임을
밝히고, 그 목표에 필요한 한 가지 정보만 확인합니다.

회사 Copilot을 쓸 수 있다면 [빠른 시작](copilot-bridge-quick-start.md)을 따라 검색 요청을
회사 안에서 실행하세요. 회사 시스템을 CareerPilot에 직접 연결할 필요는 없습니다.
결과는 비밀번호·고객/직원 정보·내부 주소·계약조건 등을 제거한 요약만 가져옵니다.
Copilot이 없으면 일정 변경, 현장 방문, 장애 escalation 같은 실제 상황을 떠올리는 질문이나
직접 제공한 안전한 메모·파일로 계속할 수 있습니다. 연결 설정 때문에 작업이 중단되지 않습니다.

첫 검색에서 유망한 사건을 찾으면 같은 기간·자료 범위에서 직접 수행한 행동과 결과 근거를
다시 확인합니다. 기본적으로 세 번 안에서 판단하고, 범위를 넓히려면 별도로 결정합니다.
충분한 근거, 새 자료 없음, 사용자 중단, 확인된 차이, 개인정보 위험에 도달하면 멈춥니다.
검색이 끝났어도 미확인 경험은 계속 미확인입니다.

여러 메일이 같은 사건을 설명하면 하나의 경험으로 묶습니다. 자료 여섯 개가 프로젝트 여섯
개가 되지 않으며, 같은 결과를 더하거나 큰 숫자만 고르지 않습니다. 역할이나 범위가 충돌하면
두 내용을 남기고 확인합니다. [본인 기여 판단](evidence-ownership.md)을 따릅니다.

CareerPilot은 안전하게 정리한 행동·범위·결과를 보여주고 실제 본인이 한 일이 맞는지
확인합니다. 확인 전에는 후보입니다. 확인 후에도 자기 확인은 USER FACT이며 외부 검증이
되지 않습니다. 팀 결과와 개인 결과를 분리하고, 모르는 결과는 모르는 상태로 둡니다.

확인된 일반화 경험은 경력 근거와 Story Bank에 연결합니다. 이후 이력서·지원 답변·LinkedIn·
포트폴리오·면접에서 같은 사실을 재사용합니다. 다른 회사 지원에는 경력 사실만 가져오며,
이전 회사의 비공개 정보·채용 가설·면접관 반응을 복사하지 않습니다.
실제 면접에서 새로 떠올린 경험도 후보로 정리할 수 있지만, 전역 저장은 별도로 확인합니다.
당시 답변과 복기는 개선된 답변으로 덮어쓰지 않습니다.

시간이 부족하거나 탐색을 원하지 않으면 이미 확인된 내용만으로 부분 초안을 만들 수 있습니다.
미확인 내용을 채워 넣지 않으며, 파일 검증 여부와 제출본 보존은 기존 v1.1 절차를 따릅니다.
