# Native clean install signoff
Development CLI evals and extracted-archive tests do not establish consumer installation/activation.
Test each platform in a new native session using the actual generated archive and record version,
package fingerprint, date, observer, surface and evidence file. Missing evidence blocks RC.

Required checks per platform:
1. clean_install: host accepts package/catalog; no runtime Python/API key/server/new account setup.
2. activation: a new session recognizes natural Korean start/job/interview/debrief/offer triggers.
3. reference_access: correct workflow/policies/templates load from installed package references.
4. full_lifecycle: synthetic W01–W09 lifecycle and original requirements/offer comparison work.
5. mock_contract: one focus/question, no praise/coaching/rubric before explicit end, focused review.
6. debrief_preserved: two rounds captured, partial/recalled unknowns explicit, earlier debrief remains.
7. isolation: Alpha/Beta do not merge, ambiguous event asks which company.
8. context_roundtrip: exported global profile/stories/requirements/each opportunity restores intact.

Use only synthetic fixtures. Native signoffs are explicit observations, never inferred from a model
CLI transcript or frontmatter check. ChatGPT UI automation may be restricted; manual user signoff
is then necessary. Do not mark an inaccessible host test passed. See evals/native-install.json.
