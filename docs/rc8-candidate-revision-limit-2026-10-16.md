# G1 보충 방침: 후보 반복 한도

사용자의 G1 승인 조건을 E 수정과 후보 결과를 보기 전에 기록한다. C 결과를 본 뒤의
명확화이며, C 전에 정한 기준으로 소급하지 않는다. 내용 동결된
[기존 방침](rc8-evaluation-policy-2026-10-16.md)과 홀드아웃 manifest는 변경하지 않는다.

- 최초 최종 후보가 미달하면 일반 원칙/해당 계약을 고친 후보는 **최대 2회** 추가한다.
  즉 최초 최종 평가 1회 + 수정 후보 최종 평가 2회가 전체 한도다.
- 각 회차 전에 수정 근거, 영향, 새 패키지/실행 식별값, 호출 수·사용량 추정과 배치 계획을
  보여주고 승인을 받는다. 자동 반복 튜닝이나 추가 결제는 하지 않는다.
- 같은 패키지·설정의 PASS/FAIL은 재실행하지 않는다. ERROR/누락만 체크포인트로 재개한다.
  재개는 새 후보 회차가 아니며, 기존 실패를 지우지 않는다.
- 후보 이름, report 경로, 홀드아웃 revision을 바꾸거나 개발용 평가를 반복해 한도를
  초기화할 수 없다. 최종 결과를 본 뒤의 수정은 위 2회에 포함한다.
- 홀드아웃을 본 뒤 수정하면 그 묶음은 회귀 묶음이다. 기존 증거를 보존하고 새 홀드아웃을
  먼저 동결한다. 다음 최종 평가 비용에는 C 전체·기존 회귀·새 홀드아웃을 포함한다.
- 수정 후보 2회 후에도 미달하면 **rc.8을 출시하지 않는다**. README의 rc.7을 유지하고
  개선 내용과 남은 실패·심판 이견·증거 한계를 문서로 남긴다.
- 안전 실패 0건, 원문 검토, 실제 실패/심판 이견 분리, 모든 자동 판정 보존 기준은 그대로다.

G1은 E 원본 수정과 무호출 도구 구현만 승인한다. 개발 호출은 변경 전후 전체 diff와
규칙 이동 대응표를 보여주는 G2, D 정리는 G3, 최종 평가는 G4에서 각각 멈춘다.
main 병합, 푸시, 태그, 릴리스 업로드는 승인 범위가 아니다.
