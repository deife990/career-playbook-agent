# 별도 변형 평가 실행기

`scripts.run_variant_evals`는 동결된 C 하네스를 수정하지 않고 `run_case()`를 재사용한다.
현재 G1 범위에서는 무호출 구현·모의 테스트만 수행했다. 실제 호출은 G2 승인 뒤다.

기본 동작은 lock 확인/계획 출력이며 모델을 호출하지 않는다. `--freeze-lock`은 새 파일을
배타적으로 생성하고 기존 파일을 덮어쓰지 않는다. `--execute`에는 승인받은 execution
fingerprint를 명시해야 한다. 이 인수는 사람의 승인을 대신하는 인증 장치가 아니다.

- development는 고정된 진단 manifest만, final은 고정된 홀드아웃 manifest만 받는다.
  manifest 자체 지문, 입력·페르소나·fixture·의존 파일 해시를 검증하고 symlink/경로 이탈을 거부한다.
- 실행 lock은 후보 패키지, 사전 주입 모드, 모델 식별값, 새 실행기 포함 scripts 전체,
  원래 프롬프트·의존 파일, 방침·반복 한도·누출 어휘 목록·규칙 대응표를 묶는다.
  개발 결과는 DIAGNOSTIC_ONLY, 최종 홀드아웃도 FINAL_COMPONENT_ONLY이며 단독 릴리스 인증이 아니다.
- 원래 CLI의 모델 기본 선택을 사용하되 실제 subject/judge 식별값이 lock과 다르면 ERROR로
  중단하고 관측 판정과 로그를 보존한다. 도구/모델이 달라지면 호출을 계속하지 말고 승인 계획을 갱신한다.
- canonical ledger는 `work/review-v2/variant-ledger`다. 패키지·시나리오 내용·입력 의존성·심판·
  컨텍스트·모델에 따른 case key로 저장하므로 report/lock 이름을 바꿔도 PASS/FAIL은 건너뛴다.
  ledger를 지우거나 다른 경로로 복제해 완료 판정을 재실행하지 않는다. 전체 실행 잠금은 중복 실행을 거부한다.
- ERROR/중단만 `--resume`으로 재개한다. 완료 subject 체크포인트를 새 attempt에 먼저 복사하고
  과거 attempt는 보존한다. 모델 호출 전 ERROR 상태를 저장하여 프로세스 중단도 재개 위치가 남는다.
  새 attempt마다 관측 결과·체크포인트·원본 로그를 남기고 배치 보고서는 새 고유 파일에만 기록한다.
- 최대 배치 6판정, 어떤 ERROR라도 배치를 중단한다. 사용량 확인은 배치 전후 운영 절차다.
  자동 추가 배치·사용량 대기 작업·결제는 없다. 한도에 가까우면 ERROR 탐색 호출을 하지 않는다.

홀드아웃 표현 검사는 별도 `scripts.check_e_leakage`가 수행한다. frozen manifest가 가리키는
입력에서 사람이 표시한 38개 고유 표현을 원문 대조해 추출한다. E 이전 `e52b59d`와 비교한
`core/`, `templates/`, `scripts/generate_adapters.py`의 추가/대체 줄을 검사한다. 삭제된 줄은
새 누출이 아니므로 차단하지 않는다. 미추적 파일도 포함하며 대소문자/호환 유니코드를 정규화한다.
대표 예시의 직종·수치는 C/개발/홀드아웃 YAML 전체와 별도로 대조한다. 일반 계약 용어는
고유 어휘에서 제외했다. 이 검사는 의미상의 누출·완전한 비공개 독립성을 증명하지 않는다.

규칙 이동 검사는 기존 가드 16블록·정책 5절의 원문과 모든 목적지, 생성 진입 13개 및
수정 전후 전체 파일 해시를 대조한다. “규칙 삭제 없음”은 이 전수 원문 대조와 작성자 검토에
따른 결론이며, 의미 동등성의 자동 증명이나 행동 합격으로 표현하지 않는다.
