# 선택형 메시지 장면 — 필요한 순간에 여는 ‘내 준비’

2026-10-20 · 사용 카드 0.5 · 12개 상황의 실제 입력·요청·확인·다음 행동 · 구현 전

본편에서 생긴 작은 고민을 메시지로 이어간다. 별도 인물·배경·루트는 추가하지 않는다. 아래는 사용 카드의 입력·요청·확인 기준이다. 실제로 재생할 선택·반응·예시·복귀는 [선택형 메시지 상세 대본](SIDE_SCENES_PLAY.md)을 따른다. 아래 인용 대사는 초기 계기 요약이며 두 파일의 메시지를 연달아 중복 재생하지 않는다. 모든 인물·자료·회사 A/B·채용 절차는 허구다. 게임 속 예시를 본인의 경력으로 외부 서비스에 보내지 않는다.

## 공통 진행

**메시지의 고민 → 짧은 가상 예시 → 내 상황으로 해보기 / 이야기로 돌아가기.** 카드마다 상황·입력·요청·결과 확인·다음 행동을 제공한다. 미열람·건너뛰기·실사용 여부는 관계나 결말에 영향을 주지 않는다.

첫 등장 위치는 장면을 추천하는 시점이다. 타이틀과 본편의 ‘내 준비’에서는 처음부터 모든 주제에 접근할 수 있다. 실제 면접이나 오퍼가 있으면 해당 작업부터 시작한다. 회차를 깨야 기능이 열리는 구조가 아니다. 실제 준비를 하러 나가는 제안은 회차 끝 한 곳에 모으고, 외전 안에서 연속 실습을 강요하지 않는다.

실제 내 상황을 제공할 곳은 CareerPilot 대화다. 게임은 파일·응답을 업로드받지 않는다. 외부로 나가기 전 게임 위치를 보관하고, 돌아오면 자기보고 후 원래 장면에 합류하는 방식으로 설계한다. 지금 작동하는 메뉴·저장은 없다.

## S01. 대화창을 닫기 전에 — 저장·새 대화·업데이트

**첫 위치:** 1화 뒤의 선택 안내. 6화에서 다시 등장. **합류:** 열기 전 장면.

> **이서:** “새 채팅 열었더니 처음 만난 사이가 됐어.”
>
> **이서:** “설치 파일 다시 올리면 되는 줄 알았지. 내 경력은 거기 안 들어 있더라.”
>
> **서안:** “그럼 인사부터 다시 한 거야?”
>
> **이서:** “응. 나한테 내 직업 물어봄.”

- **필요한 입력:** 기존 CareerPilot 대화. 복원할 때는 본인의 전체 경력 정보 묶음.
- **해볼 요청:** “내 경력 정보 전체를 내보내줘. 회사별 지원·면접 기록과 다음 할 일도 포함해줘.” 새 대화에서는 파일과 함께 “이 경력 정보로 이어서 준비하자. 복원한 회사와 면접 기록부터 확인해줘.”
- **가상 결과:** 프로필·조건·스토리·회사 A/B 기록이 포함된 묶음을 받고, 새 대화에서 포함된 회사와 면접 기록을 확인한다. 누락 파일이 있으면 부분 복원으로 표시한다.
- **직접 확인:** 설치 ZIP은 도구, 경력 정보 묶음은 본인의 자료, 게임 저장은 이야기 위치다. 경력 정보 JSON만으로 실제 PDF/DOCX까지 보관됐다고 생각하지 않는다. 제출 파일은 따로 보관한다.
- **다음 행동:** 확인된 회사·직무를 지정해 이어간다. 서비스 변경·업데이트 전에도 같은 방식으로 보관한다. 파일 생성이 안 되면 이름이 붙은 전체 JSON을 저장한다. 충돌·이전 버전은 원본을 남기고 확인한다.

## S02. 했는데 기억이 안 나 — 업무기록·Copilot Bridge

**첫 위치:** 2화 경험 확인 뒤. 3화 공고 분석에서 다시 접근. **합류:** 경험 확인 또는 지원 준비.

> **서안:** “메일 제목은 기억나. ‘일정 변경’.”
>
> **이서:** “그거 너희 회사 메일 절반 아니냐.”
>
> **서안:** “그래서 찾다가 퇴근했어.”

- **필요한 입력:** 선택한 실제 공고 또는 임시 목표, 이미 제공한 자료, 찾고 싶은 경험과 허용 기간·자료 범위. 회사 원문 전체는 필요 없다.
- **해볼 요청:** “이 공고에 쓸 경험을 점검해줘. 이미 알려준 자료부터 확인하고, 중요한 미확인 경험만 더 찾아보자.” 회사 승인 Copilot을 쓸 수 있으면 그 사실도 말한다.
- **가상 예시:** 서안의 안내 위치 변경은 이미 확인되어 재사용한다. 직접 했는지 모르는 일정 조율만 추가 확인 대상으로 남긴다. ‘더 찾지 않기 / 기억 질문 / 회사 승인 도구로 찾아보기’를 선택한다.
- **회사 승인 도구 경로:** CareerPilot이 범위를 반영한 검색 요청 작성 → 사용자가 회사 승인 환경에서 실행 → 비밀·개인정보·내부 링크를 뺀 요약을 실제로 검토 → 요약만 CareerPilot에 전달 → 직접 한 행동·범위·공유 가능 내용을 확인.
- **수동 경로:** 승인 도구가 없으면 공유 가능한 메모나 “일정이 바뀐 날 누구에게 무엇을 전달했나” 같은 구체적인 기억 질문으로 진행한다. 회사 계정 연결·새 계정·API 키는 필수가 아니다.
- **직접 확인:** CC·참석·팀 결과가 내 수행은 아니다. 여러 메시지가 한 사건이면 한 경험이다. 검색 안 됨은 경험 없음이 아니다. 충분하면 멈추고, 안전하게 공유할 수 없으면 반입하지 않는다. 확인한 요약도 자기 확인 사실이지 외부 검증 완료가 아니다.
- **다음 행동:** 정확한 행동을 확인한 뒤 스토리·이력서에 재사용. 아직 모르는 결과·수치는 비워둔다. 이미 충분한 경험은 같은 질문으로 다시 발굴하지 않는다.

확인한 경험은 같은 사실을 유지한 채 30초·60초·120초 말하기용 요점으로 바꿔볼 수 있다. 시간은 연습 목표다. 정확한 시간을 보장하지 않는다. 환경의 개인 Mail·Drive 같은 선택 연결을 쓰더라도 사용자가 허용한 자료·기간만 대상으로 하며, 회사 업무기록은 위의 승인 환경·안전한 요약 전달 경계를 유지한다. 연결이 없으면 메모·대화로 계속한다.

## S03. 이 회사 말고, 아까 그 회사 — 탐색·지원 기록 전환

**첫 위치:** 3화 공고 비교. **합류:** 선택한 가상 공고 분석.

> **이서:** “방금 보낸 건 B사고, 서안이 면접 본 건 A사. 이번엔 이름 붙여 보냈어.”
>
> **서안:** “보낸 사람이 제목을 좀 붙여주면 좋겠는데.”
>
> **이서:** “맞는 말이라 답장하기 싫다.”

- **필요한 입력:** 실제 지역·역할 조건, 공고 링크나 본문. 이미 준비 중인 회사·직무가 있다면 그 이름.
- **해볼 요청:** “내 조건으로 지원 후보를 찾아줘. 현재 모집 중인 공고와 조사할 회사를 구분해줘.” 이어서 “B사 서비스 운영 지원 공고를 분석하자. A사 준비 기록은 그대로 두자.”
- **가상 결과:** 역할이 비슷한 후보라도 필수 출근·언어·책임·상태를 따로 표시한다. 닫힌 과거 공고는 수요 참고, 확인할 수 없는 공고는 조사 후보로 남긴다. 같은 회사의 다른 직무도 구분한다.
- **직접 확인:** 역할명·지역·공고 날짜·공식 출처·모집 상태. 내가 선택했다고 지원 완료로 바뀌지 않는다. 내 경험은 재사용해도 다른 회사의 채용 가설·면접 반응은 복사하지 않는다.
- **다음 행동:** “회사별 준비 상태와 다음 할 일을 정리해줘.” 실제 지원·면접·종료가 있었을 때만 해당 사실을 알린다.

## S04. 이력서 이름이 최종최종이면 — 원본·검토·맞춤·파일

**첫 위치:** 3화 후반. **합류:** 제출 전 검토.

> **이서:** “최종 파일 보내봐.”
>
> **서안:** “어느 최종?”
>
> **이서:** “그 대답이면 일단 파일부터 정리하자.”

- **필요한 입력:** 본인의 기존 이력서 또는 확인된 경험. 맞춤 작성에는 실제 공고, 최종 파일에는 채용처 형식·언어·마감 조건.
- **해볼 요청:** 이력서가 없으면 “실제 경험을 모아 원본 이력서를 만들자.” 있으면 “기존 이력서를 먼저 검토해줘.” 지원 공고가 정해지면 “이 공고에 맞춰 조정하자.” 마지막은 “사실과 문장을 확인하고 제출용 DOCX/PDF를 검사해줘.”
- **가상 결과:** 서안의 확인된 ‘안내 위치를 바꾸고 변경 내용을 공유’한 행동을 사용한다. 근거 없는 ‘운영 혁신 주도’는 빼고, 공고에 필요한 문장을 먼저 배치한다. 화려한 표현을 줄여도 책임을 강하게 바꾸지 않는다.
- **검토 선택:** “시간이 적으니 핵심 세 가지만” 또는 “중요한 지원이라 깊게 검토”라고 말할 수 있다. 검토 깊이가 달라도 사실·파일 확인은 생략 완료로 처리하지 않는다.
- **직접 확인:** 내 행동·기간·직책·수치·책임, 공고 연결, 채용담당자에게 보이는 첫인상, 현업 추가 질문에 설명 가능한지, 다른 자료와 사실 일치. 채용담당자→현업→근거를 의심하는 면접관 순으로 검토하고 실제 약점을 수정한다. PDF/DOCX는 글자·누락·순서·한글·링크·잘림을 확인한다. 검사 불가면 미검사다. 실제 지원 시스템의 입력 결과는 허용된 화면에서 실제로 관찰했을 때만 확인한 것으로 말하며, 파일 검사가 지원 시스템 통과를 보증하지 않는다.
- **다음 행동:** 본인이 제출한 뒤 정확한 회사·직무·파일·답변·제출일을 알린다. 최신 초안으로 실제 제출본을 덮어쓰지 않는다. 파일 생성 불가 시 문구 초안과 남은 검사를 받는다.

## S05. 같은 사람인데 소개가 다르네 — LinkedIn·공개 프로필

**첫 위치:** 3화 지원 자료 선택. **합류:** 자료 준비 목록.

> **이서:** “이력서는 담백해졌는데 프로필은 아직 세계를 바꾸고 있어.”
>
> **서안:** “몇 년 전에 멋있어 보여서 썼어.”
>
> **이서:** “그때 너한테 지금 너 소개 좀 다시 해줘.”

- **필요한 입력:** 본인이 제공한 프로필 본문·화면 또는 허용한 공개 주소, 목표 역할과 이력서. 읽을 수 없는 페이지는 본문으로 대체한다.
- **해볼 요청:** “이력서와 LinkedIn의 직책·기간·성과가 같은지 먼저 검토해줘. 필요한 부분만 수정안을 줘. 영어 프로필도 같은 사실로 정리하고 싶어.”
- **가상 결과:** ‘프로젝트 주도’라는 프로필 문장이 실제 확인한 지원 업무와 충돌해 수정 대상으로 표시된다. 없는 외국어 능력·추천·경력을 추가하지 않는다.
- **직접 확인:** headline·소개·경력·skills·공개 포트폴리오의 일관성과 노출할 정보. 구직 표시가 회사에 절대 안 보인다고 가정하지 않는다. 실제 설정은 본인 화면에서 확인한다.
- **다음 행동:** 원하는 부분의 수정안만 받아 본인이 게시 여부를 정한다. 게임이나 CareerPilot이 계정 내용을 자동 변경한 것으로 표시하지 않는다.

## S06. 지원 동기 칸이 따로 있네 — 답변·커버레터

**첫 위치:** 3화 지원 자료 선택. **합류:** 제출 전 검토.

> **서안:** “이력서 올렸는데 왜 또 같은 걸 물어보지.”
>
> **이서:** “칸마다 다른 사람이 된 적은 있어. 이번엔 그러지 말자.”

- **필요한 입력:** 실제 질문·글자 수·언어·공식 안내, 지원하려는 본인의 실제 이유와 확인된 경험.
- **해볼 요청:** “이 질문에 맞는 답변 초안을 만들자. 먼저 내가 이 회사에 관심 있는 실제 이유를 확인해줘. 커버레터도 필요하면 같은 사실로 맞춰줘.”
- **가상 결과:** 정해진 글자 수 안에서 ‘왜 이 역할인지’와 확인한 행동 한 가지를 연결한다. 회사를 칭찬하는 문구를 실제 동기로 만들어 넣지 않는다.
- **직접 확인:** 질문에 답했는지, 분량·언어·회사명이 맞는지, 이력서와 사실이 같은지. 필요 없는 커버레터를 추가 과제로 만들지 않는다.
- **다음 행동:** 문구를 본인이 검토·제출하고 실제 제출 답변을 보관한다. 희망 연봉 입력은 S10에서 따로 확인한다.

## S07. 보내기 직전이 제일 오래 걸려 — 리크루터·추천·후속 연락

**첫 위치:** 3화에서 추천 문의, 4~5화에서 답장·후속 연락. **합류:** 원래 준비 장면.

> **이서:** “물어보는 건 괜찮아. 내 이름 쓰고 추천받았다고 하진 말고.”
>
> **서안:** “그 구분은 나도 해.”
>
> **이서:** “미안. 예전 내가 못 했어.”

- **필요한 입력:** 상대와의 실제 관계, 연락 목적, 공고와 확인된 경험, 원하는 말투·언어, 알고 있는 일정. 상대 연락처 원문은 필요 없다.
- **해볼 요청:** “전 동료에게 공고와 관련해 물어볼 메시지를 작성해줘. 추천은 아직 받은 적 없어.” 또는 “리크루터의 일정 요청에 답장을 준비하자. 가능한 시간은 내가 알려줄게.”
- **가상 결과:** 짧은 소개·구체적인 질문 하나·부담 없는 요청이 담긴 초안. 상황에 따라 소개 요청, 일정 답장, 감사·진행 확인 문안으로 바뀐다.
- **직접 확인:** 실제 관계·추천·가능 시간을 지어내지 않았는지, 다른 회사 이름이 섞이지 않았는지. 감사 인사를 보냈다고 합격 가능성을 추정하지 않는다.
- **다음 행동:** 본인이 확인해 보낸다. 자동 전송하지 않는다. 레퍼런스 부탁은 S12에서 별도로 준비한다.

## S08. 자료를 하나 더 만들까 — 포트폴리오·면접용 요약

**첫 위치:** 3화 자료 준비와 4화 면접 준비. **합류:** 선택한 준비 작업.

> **서안:** “발표 자료까지 만들까?”
>
> **이서:** “이번 면접에서 발표하래?”
>
> **서안:** “아니. 불안해서.”

- **필요한 입력:** 실제 지원·면접 안내, 남은 시간, 공유 가능한 경험과 자료.
- **해볼 요청:** “이 지원에 포트폴리오가 도움이 될지 먼저 판단해줘. 필요하면 공유 가능한 경험으로 구성안을, 필요 없으면 생략 이유를 알려줘.”
- **가상 결과:** 발표 요청이 없는 면접에는 새 공개 사이트 대신 확인된 경험을 짚는 짧은 개인 메모로 충분하다는 판단. 다른 상황에서 도움이 되면 사례 1~3개로 제작 목적·대상·구성을 정한다.
- **직접 확인:** 만들기/생략/보류 모두 정상 결과. 공개 포트폴리오와 선택형 면접용 1~2페이지 요약은 다르다. 고객 자료·내부 화면을 외부 제출물로 쓰지 않는다. 없는 프로젝트를 과거 성과로 만들지 않는다.
- **다음 행동:** 결정한 자료만 준비한다. 실제 발표·제출은 채용처 안내와 본인의 선택을 따른다.

## S09. 영어로 물으면 잠깐만 — 모의면접 모드·음성

**첫 위치:** 4화 연습. **합류:** 연습 종료 뒤 관계 장면.

> **서안:** “영어로 물으면 알겠는데, 대답하려고 하면 다섯 문장이 한꺼번에 와.”
>
> **이서:** “한 문장부터 말해. 다섯 개 다 기다려주진 않더라.”

- **필요한 입력:** 실제 또는 관심 역할, 연습할 라운드·언어·집중점, 가능한 텍스트/음성 환경.
- **해볼 요청:** “이력서의 내 행동을 깊게 묻는 모의면접을 하자. 질문은 영어로, 종료 후 피드백은 한국어로 해줘. 끝내자라고 하면 마칠게.”
- **선택 예시:** 기본 연습 / 이력서 파고들기 / 근거를 의심하는 질문 / 짧고 압박감 있는 질문 / 영어 / 직접 지정한 형식. 공격적 질문도 모욕으로 만들지 않는다. 모드 이름을 외울 필요 없이 목적을 말한다.
- **가상 진행:** “What did you personally change?” → 확인된 행동 하나 답변 → 후속 질문 하나. 진행 중 설명이나 칭찬을 끼우지 않는다. **“모의면접 끝내자. 피드백 줘.”** 뒤에만 답변 근거·구조·언어와 고칠 점 하나를 검토한다.
- **직접 확인:** 실제 면접 기록과 연습은 별개다. 음성 기능이 맥락을 읽지 못하면 짧은 준비 요약을 옮기거나 텍스트로 연습한다. 기록을 읽을 수 없으면 상세 발언을 복원했다고 주장하지 않는다.
- **다음 행동:** 확인된 사실은 유지하고 약한 답변 한 가지만 다시 연습한다. 질문 개수·시간만으로 자동 종료하지 않는다. 게임 자체는 음성 기능을 만들지 않는다.

종료 후에는 역할에 맞는 영어 표현, 명확하게 되묻기·생각할 시간 요청·정중한 이견 표현도 연습할 수 있다. 말의 억양·국적을 역량 평가로 바꾸지 않는다. 일정·시차·접속 정보는 실제 초대 기준으로 확인한다.

## S10. 희망 연봉은 숫자만 입력하래 — 오퍼 전 보상 대화

**첫 위치:** 3화 지원서. 4화 리크루터, 5화 진행 중에도 같은 카드 재사용. **합류:** 해당 절차.

> **서안:** “대화로 정하자고 쓰려는데 숫자만 들어가.”
>
> **이서:** “0 넣지는 마. 나도 그 생각 먼저 했어.”

- **필요한 입력:** 실제 질문·단계·국가/지역·통화·연간/월간·기본급/총보상 기준, 이미 실제로 말한 기대 조건. 현재 연봉 공개는 본인 선택이다.
- **해볼 요청:** “지금은 지원서 희망 연봉 입력 단계야. 실제 질문과 내가 원하는 조건을 기준으로 답변을 준비하자.” 리크루터 통화라면 그 단계와 실제 질문을 알려준다.
- **단계별 가상 예시:** 숫자 칸은 사용자가 넣을 실제 금액·기준을 먼저 결정한다. 리크루터 통화에는 회사의 책정 범위·역할 범위를 묻는 문안. 진행 중 역할이 달라지면 기존 대화와 비교. 정식 오퍼 전에는 기본급·변동급·출근 조건의 확인 문안.
- **직접 확인:** 임의 숫자·일률 인상률·가짜 경쟁 오퍼를 넣지 않는다. 지원 단계 질문을 정식 오퍼로 기록하지 않는다. 연봉 이력 질문의 법·세금·실수령액은 실제 지역·연도·전제와 최신 공식 근거 없이 수치나 법적 결론을 만들지 않는다.
- **다음 행동:** 본인이 결정한 답을 말하거나 입력한 뒤 실제 공개한 범위만 기록한다. 제안 문안은 과거에 말한 사실이 아니다. 실제 정식 오퍼를 받으면 S12로 이어간다.

## S11. 다음에는 다르게 말하고 싶어 — 복기·경험 확인·불합격

**첫 위치:** 5화 복기. **합류:** 다음 라운드 준비 또는 다음 지원.

> **이서:** “나도 한 군데는 떨어졌어. 지금 회사 붙기 전에.”
>
> **이서:** “다 지우고 새로 쓰려다가, 다음 회사에서 같은 경험을 물어보더라.”

- **필요한 입력:** 실제 면접의 회사·직무·라운드와 기억나는 질문·답변·추가 질문. 불합격이면 확인된 결과와 실제로 받은 피드백만.
- **해볼 요청:** “면접 끝났어. 기억나는 질문부터 복기하고 다음 라운드 준비에 반영하자.” 불합격 시 “결과가 불합격으로 왔어. 받은 피드백과 내 추측을 나눠 다음 준비를 정리하자.”
- **가상 결과:** ‘왜 본인이 바꿨나’라는 실제 추가 질문을 바탕으로 다음 연습 초점을 정한다. 복기 중 처음 떠올린 과거 행동은 공유 가능한 정확한 사실을 별도 확인한 뒤 경력 근거로 재사용한다.
- **직접 확인:** 질문→추가 질문→답변→반응→반복 주제→새 회사 정보→내 불확실성 순으로 기억을 모은다. 미소나 소요 시간으로 결과를 판정하지 않는다. 실제 당시 답변을 개선된 답변으로 바꾸지 않는다. 명시된 다음 일정이 없으면 미정이다.
- **다음 행동:** 다음 라운드가 있으면 W06 준비, 결과 대기면 확인할 다음 행동, 확인된 불합격이면 다른 지원에 재사용할 경험·수정할 실험 하나를 정한다. 공개하지 않은 탈락 이유는 미확인으로 둔다.

## S12. 축하하고, 조건을 다시 읽자 — 오퍼·협상·레퍼런스

**첫 위치:** 5화 오퍼 예고, 6화 결정. **합류:** 원래 조건을 확인한 결정 장면.

> **서안:** “연봉 줄은 벌써 다섯 번 읽었어.”
>
> **이서:** “다음 줄도 읽어. 난 집 구하고 나서 읽었어.”

- **필요한 입력:** 본인의 실제 오퍼에서 공유 가능한 조건 요약, 원래 필수·선호·피할 조건, 실제 기한. 전체 계약서를 요구하지 않는다.
- **해볼 요청:** “이 오퍼를 처음 이직하려던 이유와 비교해줘. 기본급·변동급·주식·출근 조건·미확인을 나누고, 확인하거나 협상할 문안을 준비하자.”
- **가상 결과:** 서안의 역할은 맞지만 필수 출근이 온호 생활 유지와 충돌한다. 출근 조정 가능성을 문의하는 문안과 수락/협상/보류/고사 대안을 본다. 조정이 어렵다는 가상 답변을 받은 뒤 서안이 고사한다. 합격을 위해 필수 조건을 몰래 바꾸지 않는다.
- **직접 확인:** 확정 기본급과 조건부 보너스·사인온·주식·복지를 구분한다. 귀속 조건·현금화·입사일·수습·기한·미확인 항목을 확인한다. 실수령·세금·법·환율이 필요하면 실제 전제와 최신 공식 근거로 별도 확인하며 모르는 값은 비워둔다.
- **레퍼런스 분기:** “전 상사에게 동의를 구할 문안과 전달할 경력 요약을 준비하자.” 실제 관계·허락·정확한 수행 사실을 확인한다. 허락 전에 연락하지 않는다. 게임의 윤 팀장에게 묻는 선택이 실제 사용자의 추천인 허락이 되지 않는다.
- **이력 확인 분기:** “제출한 경력과 실제 직책·기간·자격이 다른 부분이 있는지 점검하자.” 사실에 맞게 정정하고 필요한 자료만 준비한다. 경력 공백을 가짜 일로 메우지 않는다.
- **다음 행동:** 사용자가 확인·연락·수락·고사 여부를 결정하고 실제로 한 행동을 알려준다. 추천만으로 수락 상태가 되지 않는다. S01에서 최신 기록과 실제 제출 파일을 따로 보관한다.

## 제작·검증 메모

- 모든 장면은 기존 메시지 화면·텍스트 카드로 표현한다. 기능마다 새 배경·전신 이미지·분기를 만들지 않는다.
- 작품 내 문서와 CareerPilot 답변은 항상 **가상 예시 · 실제 AI 응답이 아님**으로 표시한다. 실제 응답의 순서·문구가 동일할 것을 약속하지 않는다.
- 주제별 정적 장면과 외부 서비스용 자연어 요청을 제공하는 설계다. 회사·메일·서비스·마이크를 게임이 연결하는 기능은 만들지 않는다.
- 각 장면의 ‘직접 확인’은 해당 작업을 이해하는 데 필요한 항목만 보여주고, 전체를 매번 긴 경고문으로 표시하지 않는다.
- 본편과 12개 장면 초안의 기능 범위는 [전체 기능 연결표](FEATURE_COVERAGE.md)에서 추적한다. 실제 재미·길이·사용 성공은 읽기와 지원 계정 시험으로 별도 확인한다.
